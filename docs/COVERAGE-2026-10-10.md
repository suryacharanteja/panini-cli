# Coverage verification — 2026-10-10

Python subprocess coverage is now enabled through `.coveragerc`. The repeatable runner is `scripts/test-coverage.ps1`. It records child Python processes, merges their data with append enabled, retains raw data through report generation, and rejects a run if Python source, tests or native runtime manifests change during verification.

The original 67.2% combined statement/branch measurement rose to **76.0%** in the verified snapshot. This measures execution observed by the tests; it is not a success rate or security certification.

## Tests added

CLI tests cover empty tasks, unreadable output schemas, missing sessions, local interactive commands, invalid approval modes and Ctrl+C cleanup. Provider tests cover authentication/permission errors, missing models, rate limits, connection failures, timeouts, unsupported reasoning options, successful streamed text/tool calls/usage, and closing failed streams. Provider responses are simulated.

App-server tests cover invalid requests, empty turn input, cancelled approval requests, failed/cancelled turns, thread replacement and a successful turn lifecycle. Preview cleanup tests verify that the complete owned Windows process tree is stopped before its output pipes are drained.

## Bug found and fixed

The web UAT helper stopped only the PyInstaller launcher. Its preview child could remain alive and keep output pipes open, causing shutdown to time out after the web checks had already been reported as passed. Cleanup now terminates the owned process tree, verifies that the preview port has closed, and records `previewShutdownVerified: true` before reporting overall success. The executable was rebuilt with this correction.

## Why verification used a snapshot

Another process changed source files during live verification. One run encountered a temporary import mismatch, and the source hash guard rejected another run. The final result therefore describes the fixed snapshot `build/coverage-snapshots/b002c846e585`, captured with identical source hashes before and after copying, and checked again after testing. It does not certify subsequent edits to the working tree. Earlier moving-source runs are not used for this result.

An initial snapshot web installation hit an EPERM error in a deeply nested project directory. A fresh run with a shorter output directory passed with the same snapshot executable and restricted MXC policy. The underlying cause of that installation error was not established. The successful web report is `build/cu/web-sandbox-verification.json`.

## Remaining gaps

Interactive CLI coverage is 51.7%; several prompts, configuration branches and exceptional paths still need tests. Forced termination of Python children can prevent coverage data from being flushed. The frozen executable and native Rust code are checked through UAT and existing native/integration tests; their internal execution is outside this Python coverage percentage. Interactive terminal-specific behavior and live provider behavior require separate validation.

The three skipped tests concern an unavailable legacy sandbox helper, a separately gated registry test (the independent web UAT performed the live install), and a symlink fixture requiring a missing Windows privilege. No files or branches were excluded to inflate this measurement.
