# PANINI CLI audit and closure — 2026-10-09

Release: `dist/panini-cli.exe`, PANINI CLI 2.0.0, Windows x64.

## Outcome and scope

Completed a first-party Python inventory, focused security and lifecycle review, dependency advisory scan, optimisation pass, full registered Python test suite, native SDK/FFI lint, targeted native tests, and packaged release UAT. This is engineering verification, not independent security certification or evidence of superiority over another CLI. The entire upstream MXC implementation has not received an independent line-by-line security audit here.

## Changes made in this audit

| Area | Finding and correction | Evidence |
| --- | --- | --- |
| Workspace reads | Hard-linked aliases could expose outside files. Verify the opened handle, canonical directory, regular-file type, link count and byte limit before reading. Share this implementation between file tools, preview assets and deterministic readback. | Hard-link regression; file-tool, preview and engine tests |
| Traversal | Search and completion walks could enter Windows junctions. Exclude reparse-point directories and secret directories; revalidate files before reading. Nested Git metadata is protected case-insensitively. | Full tools/completion suite; native containment tests; symlink privilege limitation below |
| Regex search | Untrusted patterns could cause excessive backtracking. Bound pattern size and per-match duration; enforce traversal deadlines. | Catastrophic-backtracking regression |
| Code search | Every matching line was retained and sorted. Maintain a bounded heap of the best 20 candidates, preserving deterministic ranking, total candidate count and evaluator reranking. | 20,001-match regression; benchmark JSON |
| Patches | Deletes used unbounded reads and lacked workspace association. Use verified bounded reads and validate all proposed files before the first mutation. | Patch rollback, approval conflict and preflight regression tests |
| MCP lifecycle | Server subprocesses lacked owned process-tree cleanup, and failed or cancelled requests could retain pending entries. Use ProcessTree, bounded startup/catalog/pending requests, schema validation and cancellation cleanup. | MCP integration tests and failed-send/cancellation regressions |
| MCP names | Sanitization could produce identical public names. Append a stable digest when sanitizing or truncating. Catalog lookups now use a dictionary. | Name-collision regression |
| Engine packaging | Frozen engine discovery appended an unsupported subcommand. Launch the executable directly. | Frozen discovery regression and actual packaged app-server handshake |
| Session storage | Unsafe identifiers and fixed temporary filenames could escape storage or race concurrent saves. Validate identifiers, use unique temporary files, and reject malformed/mismatched listing records. | Session regression and resume tests |
| Dependencies | AnyIO and Pygments had known advisories. Upgrade isolated runtime dependencies and enforce minimum versions. | Final pinned runtime scan reports no known vulnerabilities |
| Release isolation | Building from shared Python pulled in unrelated packages. Build from a dedicated environment with pinned runtime and build dependencies. | pip check; standalone bootstrap; smaller packaged release |

The shared Python environment's AnyIO, Pygments and typing-extensions versions were restored after an initial upgrade conflicted with browser-use. Secure PANINI dependencies are confined to its isolated build environment.

## Remaining design and verification limits

- CLI dispatch and agent orchestration remain large modules: CLI 1,539 lines; loop 1,082 lines; engine 501 lines. Split these by responsibility in a separately reviewed refactor. A large rewrite was not necessary for the security fixes above.
- Workspace file writes still have residual races against another host process changing directory topology between validation and mutation. Verified reads close the opened-file race; writes are not an OS filesystem transaction. Multi-file rollback is best-effort if the host fails during rollback.
- Hash-linked local receipts detect internal inconsistencies; they need an externally trusted head to prove a trailing record was not removed. Concurrent writers need additional serialization guarantees.
- The stdio app-server still needs stronger frame/queue/concurrency limits for an adversarial client. MCP client bounds do not harden the separate app-server transport.
- Approved host-side web fetching follows redirects. Restrict redirects to the approved origin, or require additional approval for another origin, before treating approval as exact network scope. This tool is separate from the MXC command network proxy.
- Interactive UI branches and live cloud-provider responses do not have full automated coverage. No live provider/model-quality benchmark or independent penetration test was performed.
- Built-assets preview does not validate arbitrary SSR, backend forwarding or hot reload. MXC isolation is not a VM; current process limits do not establish a disk quota or protection from host-kernel vulnerabilities.
- Registry installation, native probing and all closure results reflect this Windows machine. Other Windows versions, ARM64 and fresh machines with different toolchains need their own release matrix.

.\build\windows\environment\Scripts\python.exe -m pytest -q
.\build\audit-tools\Scripts\python.exe -m pip_audit -r requirements-runtime.lock --no-deps --disable-pip
.\dist\panini-cli.exe sandbox uat --web

The source-based native tests require the current native runtime to be installed first. Running the packaged UAT performs verified first-use installation. pip-audit is an audit-only tool in `build/audit-tools`, not part of the release.
